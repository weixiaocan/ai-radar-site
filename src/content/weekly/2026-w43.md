## 本周最值得亲自看的内容

### 🥇 Top 1: [AI Writes the Code. So What&#39;s Left for Engineers? - Laurie Voss, Arize AI](https://www.youtube.com/watch?v=kspZP5BgkEU)

**AI Engineer**

Laurie Voss 是 Arize AI 的开发者关系负责人，也是 NPM Inc. 的联合创始人；这期他讲的核心议题是：当 agent 让写代码几乎免费之后，工程师的工作会被推向哪个新瓶颈。

- 他引用数据说，开启自主编码 agent 的开发者写码量多 741%，但交付只快 30%，瓶颈卡在 code review 上。
- 他引用 Cognition 的 benchmark：换一个问法——作为维护者你会不会 merge 这个 PR——通过率从 87% 掉到 54%，说明 agent 缺的是「什么算好」的判断。
- 他借 Goldratt 的约束理论推演：修好一个瓶颈它只会移动，最终留给人的是决定做什么、定义什么叫好、以及让人愉悦。

你正在转向 AI 应用工程，这些关于瓶颈迁移和「什么算好」的判断，恰恰是文字摘要最容易压扁的部分；嘉宾稀缺度与反共识程度都高，值得你亲自花 1.5 小时听完他的完整推演。

**🎯 总分 7.0** · 相关度 8 · 观点 8 · 嘉宾 6 · 传播 6

### 🥈 Top 2: [Stop Telling Agents How — Dan Barrett, Raymond Weitekamp &amp; Jose Montes de Oca, OpenProse](https://www.youtube.com/watch?v=7T-gldvgfpo)

**AI Engineer**

这期由 OpenProse 团队的 Dan Barrett、Raymond Weitekamp 和 Jose Montes de Oca 出镜，核心议题是把多智能体工作流写成纯 markdown 的声明式契约——说清你要什么，而不是怎么一步步做。

- 他们演示了由 webhook 和 pull request 触发的事件驱动任务，还有一个“grumpy senior”风格的 PR 审查者。
- 从银行模型文档的端到端工作流，到把一次成功的运行固定成可复用工作流，都是可落地的东西。
- 他们还专门对比了 OpenProse 与 DSPy，并讲了如何用契约给每次运行做基准测试。

你正从转 AI 应用工程的角度摸索，这套“声明意图、让 harness 编译执行”的思路，只看文字摘要会丢掉演示里的具体写法与取舍。嘉宾稀缺度不算高，但观点偏反共识、技术密度也够，值得你亲自花 1.5 小时看完。

**🎯 总分 6.8** · 相关度 9 · 观点 8 · 嘉宾 6 · 传播 4
